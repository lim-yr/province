# 上位机控制云台和发射机构接口

完成发射机构，实现电推杆和拨弹盘的联动，待视觉测试。

本文描述本次提交中代码的实际接口与行为。对应源码位于 `RCS_code/RCS_code/STM32F405`，主要为 `xuc.cpp`、`xuc.h`、`control.cpp` 和 `motor.cpp`。

## 通信与模式

- 上位机连接 USART3，波特率 460800，UART 8位数据、无校验、1位停止位。
- 控制和上位机解码任务使用 `vTaskDelay(5)`；命令应持续发送，建议周期10～20 ms，并在每帧保留串口空闲间隔供 IDLE 接收。
- 遥控器 `s[0]=MID`、`s[1]=UP` 进入 `AUTOAIM`，接受上位机 yaw 和开火许可。
- `s[0]=MID`、`s[1]=DOWN` 进入 `FIRE`，保留遥控发射。
- 上位机不能直接切换遥控器工作模式。

## 上位机到主控

当前解码使用以下字节偏移，所有 float 为小端 IEEE 754 float32。当前字段覆盖29字节；上位机应完整发送这些字节。

| 字节偏移（从0开始） | 字段 | 类型/含义 |
| --- | --- | --- |
| 0 | header | uint8，固定 `0xA5` |
| 1～4 | pitch | float32，接收值按度转换为弧度；目前不接管 pitch 电机 |
| 5～8 | yaw | float32，单位度，与回传的 IMU yaw 使用相同坐标和零点的绝对目标角 |
| 9～12 | yaw_diff | float32，解码保存，当前不参与云台控制 |
| 13～16 | pitch_diff | float32，接收值按度转换为弧度，当前不参与云台控制 |
| 17～20 | distance | float32，解码保存，当前不参与发射判定；距离单位需双方约定 |
| 21 | flags | uint8，bit0为 `fireadvice`，1允许推出，0取消推出；其他位当前未使用 |
| 22～24 | 未使用字节 | 当前不解码，建议填0 |
| 25～28 | v_y | float32，解码保存，当前不参与控制；单位需双方约定 |

Python构造数据帧示例（仅构造，不发送）：

```python
import struct

def make_command(yaw_deg, fireadvice, pitch_deg=0.0):
    return struct.pack(
        '<B5fB3xf',
        0xA5,
        pitch_deg, yaw_deg, 0.0, 0.0, 0.0,
        int(bool(fireadvice)),
        0.0,
    )
```

`XUC::Decode()` 目前仅检查帧头，没有接收长度验证或接收CRC验证；上述29字节不是带CRC的新协议。视觉测试前需双方确认完整帧、串口分包和字段布局。

## 云台 yaw 控制

- 只有 `AUTOAIM` 下接管 yaw，并在 pitch 初始化流程返回后执行。
- 至少接收一帧、最后命令不超过100 ms、目标和当前 yaw 均为有限值时才更新目标。
- 根据 `目标yaw - IMU yaw` 求最短角差，按 `8192 / 360` 转换为机械编码误差；每次误差限制在正负500编码计数，叠加到当前电机编码值后回绕到 `[0,8192)`。
- 上位机数据超时后停止更新 yaw 目标，电机继续保持最近的目标；不会自动将电机电流清零。
- 当前没有上位机 pitch 控制闭环，pitch 字段仅接收保存。yaw 方向、零点、跨正负180度行为和实际跟随效果待视觉测试。

## 电推杆与拨弹盘联动

- `FIRE` 或 `AUTOAIM` 下启用三台摩擦轮，目标转速符号依次为负、正、负，幅值 `shoot_speed=3985`。
- 手动推出许可：`FIRE` 且 `rc.state=true`，该状态由遥控器 `ch[3]` 超出正负500触发。
- 上位机推出许可：`AUTOAIM`、`fireadvice=1`，且距最近解码帧不超过100 ms。
- 最终推出条件为“手动或上位机许可”且 PA8 输入为高；满足时 PC9 输出高电平，否则输出低电平。
- `retract = run && !push`：运行模式中没有推出命令时，视为下达缩回命令。
- `retract` 连续保持100 ms后允许拨弹，拨弹电机连续速度目标为 `-350`。供弹许可不依赖 `fireadvice`。
- 推出时取消拨弹连续转动。上位机取消许可或超时后推杆下达缩回命令，延时100 ms后恢复补弹。
- 持续发送 `fireadvice=1` 时每周期重新判断 PA8；能否连续完成推出、缩回、补弹循环依赖 PA8 实际传感器行为，尚未实机验证。
- 退出 `FIRE` 和 `AUTOAIM` 后推杆输出低、摩擦轮目标速度置零，并持续清零供弹电流和供弹状态。

这里的100 ms从缩回命令开始计时，当前没有独立的“实际缩回到位”反馈判定。

## 主控到上位机

`TxPacket` 为紧凑布局，当前发送28字节，float 同样为小端 float32。

| 字节偏移 | 字段 | 含义 |
| --- | --- | --- |
| 0 | header | 固定 `0x5A` |
| 1 | flags | bit0为detect_color（0红/1蓝），bit1为reset_tracker，bit2～6为reserved，bit7为fire_mode |
| 2～5 | roll | IMU roll，度 |
| 6～9 | pitch | IMU pitch，度 |
| 10～13 | yaw | IMU yaw，度 |
| 14～17 | aim_x | 当前保存的aim_x |
| 18～21 | aim_y | 当前保存的aim_y |
| 22～25 | aim_z | 当前保存的aim_z |
| 26～27 | checksum | 前26字节的CRC16，低字节在前 |

CRC16按 `xuc.cpp` 的反射查表实现，初值 `0xFFFF`，对应反射多项式 `0x8408`，无最终异或。`reset_tracker` 当前为0，`reserved` 当前为15。注意：`fire_mode` 当前只在 `FIRE` 为1，`AUTOAIM` 为0；视觉端若使用该位作为开火授权，需要双方调整或明确其他约定。

## 待视觉测试与已知限制

- 尚未验证上位机 yaw 跟随、帧布局、串口空闲分包、断线恢复、PA8输入与实际推出/缩回关系、连续发射及摩擦轮转速。
- 运行模式内停止拨弹时，当前代码设置 `motor_status=1`，但更新 `motor_angle_status` 的语句被注释，位置环可能追踪旧目标并产生回转。这是已知未修复事项，需要先处理并验证；退出运行模式的清零分支不受此问题影响。
